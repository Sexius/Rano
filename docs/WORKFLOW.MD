\# RANO Workflow



\## Core Policy

1\. 문제 발생 시 먼저 증상을 재현한다.

2\. 에러 메시지, 로그, 네트워크 요청을 수집한다.

3\. 바로 수정하지 말고 웹 검색으로 공식 문서와 신뢰 가능한 자료를 먼저 찾는다.

4\. 검색 결과를 기반으로 원인 가설을 1\~3개로 정리한다.

5\. 한 번에 한 가지 원인만 수정한다.

6\. 수정 후 반드시 실행하여 결과를 검증한다.

7\. 해결되지 않으면 다음 가설로 넘어간다.

8\. 관련 없는 리팩토링, 구조 변경, 파일 이동은 금지한다.



\---



\## Debug Process

1\. 증상 요약

2\. 재현 방법

3\. 로그 및 에러 메시지 확보

4\. 웹 검색 (공식 문서 우선)

5\. 원인 후보 1\~3개 정리

6\. 하나만 수정

7\. 실행 및 검증

8\. 변경 파일 및 이유 정리



\---



\## Search Policy

\- 공식 문서를 최우선으로 참고한다.

\- 공식 문서가 없으면 신뢰 가능한 기술 자료를 참고한다.

\- 검색 근거 없이 추측으로 수정하지 않는다.



\---

\## External API \& Security Policy

\- 외부 데이터 API를 frontend에서 직접 호출하지 않는다.

\- API 키가 필요한 요청은 반드시 backend에서 처리한다.

\- VITE\_\* 환경변수에 API 키를 저장하지 않는다.

\- vite.config.ts의 define 등을 사용하여 API 키를 클라이언트 코드에 주입하지 않는다.

\- 정적 이미지, 폰트 등 CDN 자산 로딩은 허용한다.

\- 단, CDN 의존성이 문제를 일으키면 backend proxy 또는 자체 호스팅으로 전환한다.

\---



\## Change Policy

\- 한 번에 하나의 문제만 수정한다.

\- 여러 문제를 동시에 해결하려 하지 않는다.

\- 기존 동작을 깨뜨릴 가능성이 있으면 먼저 설명한다.

\- 불필요한 리팩토링은 금지한다.



\---



\## Output Format

작업 완료 후 반드시 아래 형식으로 보고한다.



\- 증상

\- 원인 가설

\- 검색 근거

\- 수정 내용

\- 변경 파일

\- 검증 결과

\- 남은 문제
